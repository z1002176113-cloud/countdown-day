# 移动端倒数日工具 App 项目规划（React 技术栈版）

> 来源：飞书 Wiki（https://zcnzogkht6d3.feishu.cn/wiki/O3a7w7dXLia49Zkok9YcltkLnwh）
> 本文件由 Wiki 原文转换为 Markdown，内容不做增删改。

背景：放弃 Flutter，改用 React 生态做移动端；目标不变：学习为主、MVP 最小闭环、纯本地无后端、可上线、少量真实用户、防止烂尾。

## 一、技术栈调整说明

React 做移动端有两条主流路线：

1. React Native（推荐选这个）
   - 使用 React 语法，原生渲染，真正移动端 App，可以打包 APK / iOS 安装包，支持桌面小组件、本地推送通知，可以上架应用商店，简历含金量高。
   - 一套代码安卓/iOS，JS/TS 技术栈，和 Web React 技能打通。
2. 不推荐：React + PWA（网页套壳）
   PWA 无法实现桌面小组件、系统本地通知完整能力，这两个是本项目核心差异化功能，PWA 做不到，所以排除。

✅ 确定技术栈：React Native + TypeScript

### 完整技术栈清单

- 框架：React Native（Expo 工作流，强烈推荐实习生用 Expo，环境配置简单，少踩原生编译坑）
- 语言：TypeScript（类型约束，简历加分）
- 本地存储：expo-sqlite 或者 @react-native-async-storage/async-storage
- 本地通知提醒：expo-notifications
- 桌面小组件：expo-widgets（Expo 提供小组件能力；小组件属于原生层，JS 逻辑有限）
- UI 组件：React Native 内置组件 + react-native-paper（现成 UI 库，不用从零写样式，节省大量时间）
- 状态管理：Zustand（轻量，学习成本低，不要上 Redux，过重）
- 打包构建：Expo EAS Build，构建 APK / iOS 包；可做测试版，也可用于上架

架构依然：纯本地 App，无后端、无服务器、不做账号云同步。

## 二、功能范围【完全不变】

### ✅ MVP 必做（一期，必须完成）

1. 倒数事件 CRUD：新增、编辑、删除、查看事件
2. 时间计算逻辑：剩余天数 / 已过天数，正倒计时
3. 本地持久化存储，重启 App 数据不丢失
4. 系统本地通知：事件到期、提前提醒
5. 桌面小组件：桌面展示倒数事件（核心卖点）
6. 基础 UI 与多机型适配

### ⏸️ 二期可选（有余力再做，不做不影响交付）

- 主题配色、自定义背景
- 事件标签分类
- 置顶、星标事件
- 简单统计页面

### ❌ 坚决不做（规避工作量，防烂尾）

账号登录、云同步、番茄钟、打卡日历、会员、广告、社交分享、多语言。

## 三、分阶段开发计划（总周期依旧 4 周，适配 React-Native/Expo）

### 第1周：环境搭建 + 项目骨架

1. 初始化 Expo + TypeScript 项目，配置项目目录结构
2. 引入依赖：Zustand、react-native-paper、存储库
3. 搭建页面骨架：首页列表页、新增页、编辑页，静态 UI
4. 编写时间计算工具函数（倒计时、剩余天数、已过天数）

产出：项目可运行，页面架子全部就绪，时间工具函数完成。

### 第2周：核心业务逻辑开发

1. 封装本地存储层，实现事件数据增删改查
2. Zustand 管理全局事件状态
3. 页面绑定真实数据：新增、编辑、删除事件
4. 列表排序：临近事件优先展示
5. 验证：重启 App 数据不丢失

产出：核心倒数业务完整跑通；没有通知、小组件；但是 App 已经可以正常使用。

### 第3周：差异化能力开发（通知 + 小组件 + UI 打磨）

1. 接入 expo-notifications，申请通知权限，实现到期/提前提醒
2. 使用 expo-widgets 开发桌面小组件，展示倒数事件
3. UI 细节优化，处理不同屏幕适配
4. 修复交互 bug

产出：完整 MVP 成品 App，拥有竞品核心能力。

### 第4周：测试、打包、文档、小范围分发

1. 全流程测试：时间计算错误、权限异常、闪退、小组件刷新异常
2. 使用 EAS Build 构建安卓 APK 测试包
3. 编写项目 README：架构说明、功能截图、部署方式
4. 整理简历项目描述
5. 小范围分发获取种子用户（同学、开发者社群）

产出：完整可交付项目，作品集素材齐全。

## 四、风险点提醒（React-Native 你必须提前知道）

1. 小组件是难点
   React-Native 本身不直接写小组件；expo-widgets 做封装，能力有限。小组件调试很折磨，很容易出现数据不刷新。
2. iOS 模拟器/真机权限坑：通知权限、小组件权限，真机才可以完整测试。
3. Expo 优势：不用配置 Android Studio/Xcode 编译环境；但是部分原生能力依然需要真机调试。

## 五、动力保障（你的情况不变）

1. 不靠兴趣驱动，靠小任务里程碑驱动；
2. 设置最低工作量；
3. MVP 完成即可结束，不必硬迭代二期；
4. 若小组件长期卡住，可以降级，保留其他全部核心功能，项目依然有价值。

## 六、简历学到的技术点（React-Native 方向）

- React Native + TypeScript + Expo 移动端开发
- Zustand 状态管理
- 本地数据库持久化封装
- 系统权限、本地推送通知
- Expo Widgets 桌面小组件开发
- App 打包、EAS Build 构建流程
- 移动端需求分析、MVP 产品设计

## 七、项目成功验收标准（不变）

1. App 可正常安装运行，无严重闪退
2. 倒数事件增删改查、时间计算准确
3. 本地存储重启不丢数据
4. 通知提醒可用；小组件尽量可用（实在不行可作为待完成优化点写进文档）
5. 小范围真实用户试用
6. 完整代码仓库 + README 文档
