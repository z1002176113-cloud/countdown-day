# 最终极简 MVP（项目范围与两周开发节奏）

## 一、最终极简 MVP（只保留这些，其余全部砍掉）

### ✅ 必做核心功能（两周做完即完美交付）

- 新增 / 编辑 / 删除 倒数事件
- 精准倒计时计算（剩余天数、已过天数）
- 本地数据持久化（重启不丢数据）
- 本地消息通知（事件到期提醒）
- 简洁可用 UI、事件列表展示

### ❌ 全部砍掉（节省海量时间，杜绝烂尾）

- 桌面小组件（最耗时、最容易卡壳的功能直接删）
- 主题、壁纸、自定义背景
- 事件分类、标签、置顶、收藏
- 数据统计、图表
- 任何动画、特效、复杂适配

### 项目定位

纯前端客户端项目、0 后端、0 服务器、0 接口，适合实习作品集、全程自己独立开发、极易复盘、绝不烂尾。

## 二、整体开发节奏（适配你：无兴趣、任务驱动、稳落地）

- 每日开发时长：40–90 分钟，不熬夜、不内卷
- 卡住 40 分钟解决不了 → 跳过，次日攻克，不内耗
- 以「完成可用版本」为目标，不以完美为目标

## 三、第一周（1-7 天）搭建 + 核心业务全部落地

本周结束：App 已经可以正常使用，完整具备倒数日核心功能

### Day1：环境搭建 + 项目初始化

- Expo + TS 初始化项目
- 清理默认代码，搭建标准化目录结构
- 安装核心依赖：Zustand、RN Paper、本地存储

### Day2：工具函数 + 全局配置

- 封装项目通用样式、配色
- 完成核心时间工具函数（倒计时计算、日期格式化）

### Day3：页面骨架开发

- 首页列表页面 UI
- 新增事件页面 UI
- 页面路由跳转逻辑

### Day4：本地存储封装 + 数据结构定义

- 定义事件 TS 类型
- 封装本地存储增删改查基础方法

### Day5：状态管理 + 新增事件功能完成

- 搭建 Zustand 全局状态
- 完成事件新增、自动刷新列表功能

### Day6：编辑 + 删除功能完成

- 事件编辑逻辑
- 事件删除逻辑
- 列表实时更新

### Day7：第一周复盘 + 数据持久化校验

- 重启 App 验证数据不丢失

- 本周产出：完整可用的倒数日基础版本
